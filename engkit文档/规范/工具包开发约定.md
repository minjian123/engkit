# 工具包开发约定

> 包内红线与提交前的自检清单

[文档首页](../文档首页.md) › 规范　|　[← 概述](../概述/工程化工具包说明.md)

## 1. 三条红线 <a id="rules"></a>

1. **包内无仓名字面**：`src/engkit/**` 不得出现任何仓库的文档根、源码根、顶层包名或服务名；需要区分仓差异时**加配置键**，不改代码。用例 `tests/test_guards.py` 负责机器断言。
2. **单一来源**：选测推导、并行档位、覆盖率门禁、重命令判定各只有一份实现。各仓入口脚本只允许「转发参数 + 透传退出码」，不得复制逻辑。
3. **不静默退化**：任何退化（全局变更 / 基础模块 / 无引用者 / 扩圈不收敛 / 基准不可解析）都必须打印原因，并计入度量行。

> **规则数据只在配置（`13_06`）**：基座校验器（`engkit base <名>`）的**判定**在包内，**规则数据**（清单路径 / 标识符段 / 表前缀 / 白名单 / 枚举名 / 模板键位 / 正则与词表）一律落各仓 `[rules.<名>]`；包内不得写字面，也不得为某仓留缺省值兜底——缺段即退 2。

> **单一来源的延伸（`13_07`，已落地）**：**工具链配置与版本**同样只有一份——ruff 规则基线在 `toolchain/ruff-base.toml`，ruff / pyright 版本在 `[project.optional-dependencies].devtools`。各仓 `[tool.ruff]` 段**只允许** `extend` + 本仓专属项（`target-version` / `known-first-party` / `src`），**不得**再写 `line-length` / `select` / `ignore`；工具版本**不得**在各仓 `pyproject.toml` 另行声明。受检仓配置清单登记在本仓 `engkit.toml` 的 `[toolchain].ruff_configs`，护栏用例为 `tests/test_toolchain.py`（Kiwi 2360）。

## 2. 代码约定 <a id="code"></a>

- 只用标准库；确需三方能力时**降级而非硬依赖**，并在输出里明示「跳过（缺 X）」；
  **唯一例外是 `pytest-xdist`**：并行档位（`-n`）由它提供，随本包安装（`dependencies`），使各接入仓**无需自行声明**该测试插件；它缺失时并行档位仍须显式降级为串行（不静默失败）；
- 配置解析一律经 `config.py` 的 dataclass，未知键报错；
- 对外行为（参数名、退出码、度量行格式）改动视为**破坏性变更**：先改各仓调用面，再发改包版本；
- 每个对外函数带中文 docstring（Args / Returns / Raises），与平台代码同口径；
- **工具链基线**（`toolchain/ruff-base.toml`）只放各仓一致项；本仓专属项（`target-version` / `known-first-party` / `src`）**不得**写入基线——engkit 自身是 `>=3.11` 的库，接入仓可能是更高版本；
- `devtools` 组的版本用 **`==` 严格同版**（不用 `>=` 下限——实测下限会让各仓落到不同补丁版）；改版本属对外行为变更，按 §4 的升级流程发版。

## 3. 提交前自检 <a id="checklist"></a>

```bash
uv run ruff check .
uv run ruff format --check .
uv run pyright
uv run pytest --cov=src/engkit --cov-branch --cov-fail-under=100
uv run engkit push              # 推送入口：预检通过才推送（开发中未提交会被拒，属预期）
uv run engkit push --check      # 只跑预检、不推送（开发中验证引擎用）
```

- 覆盖率门槛口径见《AI开发规范》「覆盖率要求」节；
- 四条全绿再提交；改到 `guard` / `preflight` 的判定逻辑时，必须同时跑 `tests/test_guards.py`；
- 自举烟雾在 CI 里跑（`engkit preflight --fast`，CI 环境不受「本地拒绝」限制）；本地开发中用 `engkit push --check` 验证整条链路。

## 4. 版本与分发 <a id="release"></a>

- 各仓以 **git 源依赖锁 rev** 或路径探测引用同一份实现，不发布到私有 PyPI；
- 升级流程：改 `pyproject.toml` 版本 → 打 tag → 各仓改 `rev` / `ENGKIT_REV` → 跑该仓三条命令验证；
- **工具链版本升级**（`13_07`）：改 `devtools` 组版本 → 提交并记 SHA → 各仓改 `rev` 与 CI 的 `ENGKIT_REV` → `uv lock` → 跑该仓 `ruff check` / `format --check` / `pyright` 确认零差异；触点只有 2 处（各仓 `rev` + CI 变量），升级前后必须实测诊断一致；
- 破坏性变更需在《工程化工具包说明》标注并同步所有接入仓。
