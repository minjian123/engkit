## 3. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | 自测条目形态不止「python 脚本」（测试里用 `echo` / `-c`），同进程 runner 直接判失败 | 形态不支持时**回退子进程执行**（回退到执行，不是跳过）；文档写明 |
| 2 | **自污染**：记录文件写在仓内，被计入输入指纹 → 写一次记录指纹就变一次，复用永不命中（实测 `same key False`） | 新增 `_is_artifact`：排除 `.git/`、`reuse_file`、`audit_file`、`coverage.data_file`（含按 pid 落盘的派生文件）；不依赖各仓 `.gitignore` 已忽略 `.cache/` 这一隐含前提 |
| 3 | 只取 `git write-tree` 会漏掉「改了但没 add」的文件（假命中） | 输入指纹并入工作树未提交内容（按输入集过滤后取内容哈希），宁可多失效 |
| 4 | 记录缓存按 `mtime` 校验，同秒内改写可能读到旧值 | 改为 `(mtime_ns, size)` 双校验 |
| 5 | 迷你仓闭包 2/3 ≥ `base_ratio` 0.6 → 单测里直接退化 | 测试用 `base_ratio=1.0` 局部替换；真实仓（10 工程 / 948 文件）改叶子模块闭包通常十几个文件，不触发 |
| 6 | `_read` 的 `FileNotFoundError` 分支在 `_load` 前置 stat 后不可达 | 按规范加 `# pragma: no cover - 不可达原因` |
| 7 | **推送后发现全仓覆盖率 99%**（CI 会红）：`cli._cmd_checks` 未测、`config` 两处非法值分支、`preflight` 的 `reuse=false` 通路、`selection` 闭包两个分支 | 补 4 份用例（含新增 `tests/test_cli_checks.py`）达 100%；根因是「推送前只验了新模块单文件覆盖率」，已写入测试记录作教训 |
| 8 | 逐文件跑覆盖率得到假缺口（38 份数据对应 36 个文件，pid 复用覆盖采集数据，最大模块虚报缺 62 行） | 改为「一次跑全部测试文件」，单份采集数据；与 CI 同款命令对齐 |

## 5. 偏差与遗留 <a id="deviation"></a>

| 项 | 性质 | 归口 |
| --- | --- | --- |
| 单进程 runner 不设单条超时（同进程无法中断） | 设计边界（已在《详细设计》§5 与概述文档写明） | `process` 模式提供超时保护；如后续需要，改为「线程 + 超时」方案另立项 |
| 定向用例段（`scoped_tests`）不参与复用 | 设计边界：产出为覆盖率采集数据，跳过会让排障读到旧数据 | 本专项不做 |
| 前端 typecheck 仍是 41% 大头 | 已知未覆盖 | 二期「步骤内产物缓存」 |
| 耗时目标绝对值待基准采样后回填 | 未闭环 | 下一次真实推送（模块收尾）采样后回填计划表 |
| engkit 未推送期间 CI 跑旧版 | 前置依赖 | 计划表验收段已分两行登记；推送由用户另行指令 |
