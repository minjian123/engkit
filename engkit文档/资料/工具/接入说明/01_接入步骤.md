## 1. 新仓接入五步 <a id="steps"></a>

| 步 | 动作 | 产物 |
| --- | --- | --- |
| 1 | 仓根放一份 `engkit.toml`（按 §2 模板，只填本仓路径与规则） | `engkit.toml` |
| 2 | 让包可被调用：安装（`pip install -e .` / `uv add`）或以 git 源依赖锁 rev 引用 | `pyproject.toml` 依赖声明 |
| 3 | **接入工具链基线**（`13_07` 起）：`[dependency-groups]` 写 `engkit[devtools]`（取得 ruff / pyright 版本），`[tool.ruff]` 只写 `extend` + 本仓专属项（见《工程化工具包说明》§5） | `pyproject.toml` |
| 4 | 本地验证三条命令：`engkit links` / `engkit docs-scope` / `engkit preflight --fast` | 全绿 |
| 5 | CI 接线：`base` 阶段加链接与口径两步，测试阶段改用 `engkit preflight --push`（CI 环境不设脏树闸门）；**凡跑 ruff / pyright 的 job 需先有 engkit 克隆**（基线按文件路径读取）。`workflow.rules` **只放行 `web` / `api` 手工触发**（2026-10-26 起推送不触发流水线，新仓照抄该口径，勿加 `push` / `merge_request_event`） | `.gitlab-ci.yml` |

> **路径探测兜底**：仓内脚本若只想「有克隆就能用」，可先 `import engkit`，失败时按 `ENGKIT_HOME` → 同级 `../engkit` 注入 `sys.path`；CI 侧按锁定 SHA 克隆一步即可。

> **开发环入口（推荐一并接入）**：仓内放 `scripts/tools/preflight/测试改动内容.sh` / `.bat` 转发 `engkit run-changed`（bms 走 `engkit_boot` 薄包装，mdm 直接 `uv run engkit`），`engkit.toml` 配 `[selection] depth = "direct"` + `ruff_cmd` / `ruff_config`。开发期间改完即测只跑改动相关（直接依赖测试 + 前端受影响包 + 改动文件 ruff、无覆盖率）；推送前预检固定 `closure` 并保覆盖率门禁，两档分工见《工程化工具包说明》§4.2。

> **工具链基线的两个前提**：① 各仓必须有 engkit **克隆**（ruff 的 `extend` 读文件路径，读不了安装包内资源）；② 基线路径只能写**相对路径**（ruff 不展开环境变量）。缺克隆时 ruff 直接报 `Failed to load extended configuration` 并退出 2——这是有意为之，不做仓内副本兜底。

## 2. 配置模板 <a id="template"></a>

```toml
[repo]
name = "<仓名>"

[docs]
root = "<文档根>"
skip = ["<文档根>/用户文档/"]

[docs.scope]
whitelist_dirs = ["规范/", "资料/", "用户文档/"]
plan_dir_pattern = "^项目/[^/]+/计划/"

[backend]
root = "backend"
groups = ["libs", "services"]
projects = ["libs/<工程>", "services/<服务>"]
coverage_packages = ["<顶层包名>"]

[pytest]
cmd = "uv run pytest"
cwd = "backend"

[selection]
# 开发环（`engkit run-changed`）依赖深度：direct = 只认直接 import；预检固定 closure 不受影响
depth = "direct"
# 开发环只对改动文件跑 ruff（静态全量留推送前预检）；空串即跳过
ruff_cmd = "uv run --project backend ruff"
ruff_config = "backend/pyproject.toml"

[frontend]
root = "frontend"
test_cmd = "pnpm --filter {package} test"   # workspace 不在仓根时用 `pnpm -C <目录> --filter {package} test`

[coverage]
data_env = "<前缀>_COVERAGE_DATA"
source_env = "<前缀>_COVERAGE_SOURCE"
fail_under = 100
plugin = "engkit.coverage_plugin"
# 采集数据落点：仓内缓存目录（`.cache/` 已忽略），**不落仓库根 / backend/ 根**；
# 插件与 `engkit coverage` 会自动建父目录
data_file = ".cache/coverage/.coverage"
```

`projects` 与 `coverage_packages` 是**登记项**：`engkit preflight --self-test` 会把「自动发现的工程」与它们对账，漏登记即自检失败。

**覆盖率采集与拦截入口**：pytest `addopts` 需同时加 `-p engkit.coverage_plugin`（与 `[coverage].plugin` 同值），
插件导入即启动采集（早于被测模块导入）并挂上重命令拦截；仓内无需另写采集或拦截实现（见《工程化工具包说明》§4.4）。

### 2.1 工具链基线（`pyproject.toml` 片段，`13_07` 起） <a id="template-toolchain"></a>

> 基线文件 `engkit/toolchain/ruff-base.toml` 与 `devtools` 组已落地；接入后 ruff 规则与工具版本都只在 engkit 一处维护。

```toml
[dependency-groups]
dev = ["engkit[devtools]"]          # ruff / pyright 版本随 engkit 下发，本仓不再声明版本

[tool.uv.sources]
engkit = { git = "<GitLab>/bms/engkit.git", rev = "<SHA>" }

[tool.ruff]
# 规则基线在 engkit 仓根 toolchain/ruff-base.toml（相对本配置文件所在目录）
extend = "../../engkit/toolchain/ruff-base.toml"
target-version = "py3xx"            # 本仓属性，不进基线

[tool.ruff.lint.isort]
known-first-party = ["<本仓包名>"]   # 本仓属性，不进基线
```

**不要**在 `[tool.ruff]` 里再写 `line-length` / `[tool.ruff.lint].select` / `.ignore`——这些是基线内容，复制即违背单一来源（`tests/test_toolchain.py` 有机器断言）。

**登记受检配置**：护栏用例跑在本仓，受检的仓配置清单登记在**本仓 `engkit.toml`** 的 `[toolchain].ruff_configs`（相对 engkit 仓根，平级仓写 `../<仓>/backend/pyproject.toml`；路径不存在即跳过，故单仓 CI 不受影响）。新仓接入时若希望被自动巡检，在 engkit 仓补一行登记并提交。

## 3. 已接入仓实例 <a id="instances"></a>

### 3.1 bms（基座，git 源依赖 + 路径探测兜底 + 薄包装） <a id="bms"></a>

- 配置：仓根 `engkit.toml`（文档根、后端 10 工程、前端三组、全局与特殊路径规则、30 个预检步骤、7 项自测）；
- 取得方式：`13_07` 起以 **git 源依赖**安装 `engkit[devtools]`（与 mdm 同构，ruff / pyright 版本随之统一）；
  `scripts/tools/preflight/engkit_boot.py` 的路径探测保留为兜底（已安装则直接可用）；
- 工具链：`backend/pyproject.toml` 的 ruff 段只 `extend` 基线，规则段不再复制；
- CI：抽公共片段「按 `ENGKIT_REV` 克隆并 `export ENGKIT_HOME`」，凡跑 ruff / pyright 的 job 也引用该片段，命令原文不变。
- 开发环：`scripts/tools/preflight/测试改动内容.sh|.bat`（`测试改动内容.py` 薄包装 → `engkit run-changed`），依赖深度 `direct`。

### 3.2 mdm（产品仓，git 源依赖锁 rev） <a id="mdm"></a>

```toml
[tool.uv.sources]
engkit = { git = "<GitLab>/bms/engkit.git", rev = "<SHA>" }
```

- 本地与 CI 均以 `uv run engkit ...` 调用（`uv sync --frozen` 按 rev 拉取）；
- 已启用 `links` / `docs-scope` / `preflight` 三项；
- 开发环：`scripts/tools/preflight/测试改动内容.sh|.bat`（转发 `uv run engkit run-changed`），依赖深度 `direct`，前端 `test_cmd` 带 `-C frontend`；
- 工具链：依赖写 `engkit[devtools]`、ruff 段 `extend` 基线（`13_07`）。

## 5. 排障 <a id="trouble"></a>

| 现象 | 处置 |
| --- | --- |
| `未找到 engkit.toml` | 在仓根执行，或用 `--config` 指到配置文件 |
| `配置 xxx：未知键` | 配置写错或版本不一致：对照《工程化工具包说明》§4 字段表 |
| `自动发现的工程全部登记` 失败 | 新增工程未登记到 `projects` / `coverage_packages` |
| `重命令守卫` 拒绝执行 | 用 `engkit run_once -- <原命令>` 包装；排查包装器自身问题可 `ENGKIT_ALLOW_UNWRAPPED=1` |
| `未采集到覆盖率数据` | 采集插件未启动：检查 `[coverage].plugin` 与 `PYTHONPATH` |
| `Failed to load extended configuration` | engkit 克隆缺失或 `extend` 相对层级写错：按 §1 克隆，并核对「相对本配置文件所在目录」的层级 |
| ruff / pyright 版本与本仓 `uv.lock` 不一致 | 依赖未写 `engkit[devtools]`，或 `uv lock` 未重跑：按 §2.1 改依赖后 `uv lock` |
